# Git Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Link a workspace to a git repository and keep it in sync with one Sync button. The button commits with a
reviewed message, pulls with field-level merging of JSON files, and pushes. Pull only and Push only sit in its menu.
Conflicts left after the field-level merge are resolved per item in the app. The user can also open a workspace by
cloning a repository.

**Architecture:**

- **Running git.** Main-process code in `src/main/git/` runs the system `git` binary with `execFile`, never a
  shell. That way the user's SSH agent, credential helper and config apply.
- **Merging.** A pure 3-way JSON merge (`jsonMerge.ts`) resolves conflicted workspace files after `git merge`
  stops. It reads the base, ours and theirs versions from the index stages. Only the conflicts it cannot resolve go
  to the user.
- **UI.** The renderer gets a sync indicator and a split button in the status bar, plus three dialogs (Set up sync,
  Commit, Conflicts) and an `Open from Git` entry.

**Tech Stack:** Electron 44, Node `child_process.execFile`, TypeScript strict, React 19, zustand, Vitest. No new
dependencies.

**Spec:** `docs/superpowers/specs/2026-10-20-astral-maria-design.md`, decision 6:

> uses the system `git` binary ... "Sync" does: commit local changes ..., fetch, merge the remote, push. If the
> merge conflicts, stop, list the conflicted files, and offer "keep mine" / "keep theirs" per file plus "open in
> editor". No force-push, ever.

**User decisions of 2026-10-22, which refine the spec:**

- A single **Sync** button, with **Pull only** and **Push only** in its menu.
- A **Commit dialog** with the list of changes and an editable, pre-filled message, instead of a silent automatic
  message.
- A **field-level merge** of JSON files. The user is asked only about real conflicts, and per item rather than per
  file.

**UI binding:** `docs/superpowers/specs/2026-10-21-postman-measurements.md`.

## Global Constraints

- **Running git.** Every invocation goes through one `runGit(cwd, args, opts)` built on `execFile('git', args)`,
  with no shell.
  - **Environment:** `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `LC_ALL=C`, plus the user's environment.
  - **Timeouts:** 120 s for network commands (fetch, pull, push, clone), 30 s for the others.
  - **Cancelling** kills the process.
- **Commands that are never run:**
  - `push --force`, `push -f`, `--force-with-lease`, `reset --hard` on user commits, `clean`;
  - `config --global`;
  - anything that rewrites published history.

  Abort uses `merge --abort` only. A test asserts that no forbidden argument is ever passed to `runGit`.
- **Git identity.** The app never changes the global git identity. When `user.name` or `user.email` is missing, the
  Commit dialog asks for them and writes them with `git config --local`.
- **Before a git operation that touches the working tree,** the renderer flushes all drafts. Afterwards it refreshes
  collections and environments. Tabs whose file changed on disk follow the existing changed-on-disk rules.
- **`.local/`** stays ignored, and secrets never reach git. Before every commit, the app checks that `.gitignore`
  contains `.local/`, adds it if missing, and refuses to commit any path under `.local/`.
- **Messages.** Errors are user-facing and specific:
  - git is not installed: `Git is not installed. Install the Xcode Command Line Tools: xcode-select --install`;
  - authentication failed: `Git could not sign in to <remote>: <git's first stderr line>`;
  - there is no upstream yet: the first push sets it, with `push -u origin HEAD`;
  - the push was rejected: `The remote has new changes. Pull first`. This only happens with Push only; Sync pulls
    first.
- **Commits** are conventional. They end with:

  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01W7UnCdyUfoFmAZKAA878zM
  ```

  Check that `git config user.email` is `stas.lisavoy@icloud.com`. Never change the identity, and never push.
- **Implementers run** only `npm test` and `npm run typecheck`. Git tests may run the real `git` against temp
  directories and local bare repositories, with no network. They never run build, e2e, dev or Electron.
  - **Test isolation.** Tests set `GIT_CONFIG_GLOBAL` to a temp file and `GIT_CONFIG_NOSYSTEM=1`, and set the
    identity per repo, so they never read or touch the user's real git config.
- **Branch:** `feat/git-sync`, cut from `main`.

## Review Focus

1. **Sync with no local changes and nothing new on the remote** completes without creating an empty commit and
   reports `Up to date`. *Test in Task 3.*
2. **Two people add different requests to the same folder.** The `order` arrays in `folder.json` merge as a union,
   with no conflict, and both requests appear. *Test in Task 2 (merge) and Task 3 (end to end with two clones).*
3. **Remote deleted, local edited.** The item is offered as `Deleted on the remote` with `Keep mine` (restore it) or
   `Delete`. The same holds the other way round. *Test in Task 3.*
4. **Abort in the middle of conflict resolution** restores the exact pre-merge state. Local commits made by this
   Sync are kept, and nothing is pushed. *Test in Task 3.*
5. **A merge that cannot be parsed.** When a conflicted JSON file is invalid in one of its versions, it falls back
   to whole-file `Keep mine` / `Keep theirs` / `Open in editor`. It never writes a broken file. *Test in Task 2 and
   Task 3.*

### Task 2: Three-way JSON merge

**Files:**
- Create: `src/main/git/jsonMerge.ts`
- Test: `tests/main/jsonMerge.test.ts`

**Interfaces:**
```ts
export type FileKind = 'request' | 'folder' | 'collection' | 'environment' | 'workspace' | 'other'
export function fileKind(relPath: string): FileKind   // by name: *.request.json, folder.json, collection.json, environments/*.json, workspace.json
export interface FieldConflict { path: string; label: string; ours: unknown; theirs: unknown; base: unknown }
export type MergeOutcome =
  | { kind: 'merged'; text: string }                                   // pretty JSON, 2-space, trailing newline, like writeJsonAtomic
  | { kind: 'conflicts'; partial: unknown; conflicts: FieldConflict[] } // partial has every non-conflicting change applied
  | { kind: 'unmergeable'; reason: string }                            // a side is missing/invalid JSON or kind 'other'
export function mergeJson(kind: FileKind, base: string | null, ours: string | null, theirs: string | null): MergeOutcome
export function applyChoices(kind: FileKind, partial: unknown, conflicts: FieldConflict[], choose: (c: FieldConflict) => 'ours' | 'theirs'): string
```

**Merge rules.** A side counts as changed when it differs from base, compared deeply.

- **Scalars and objects** merge recursively, field by field. Both sides changing a field the same way is not a
  conflict. Both changing it differently is a conflict at that path.
- **Keyed arrays** merge element by element.
  - **Which arrays are keyed:**
    - request `params`, `headers` and `body.fields`, keyed by `key`;
    - collection `variables`, keyed by `key`;
    - environment `variables`, keyed by `key`.
  - **Merging elements.** An element added on one side is added. Removed on one side and unchanged on the other: it
    is removed. Removed on one side and changed on the other: a conflict. Changed on both sides: a recursive merge.
  - **Order.** Theirs' order, then ours' additions in ours' relative order.
  - **Duplicate keys.** If any version has duplicate keys, the array is treated as a single atomic value.
- **`order` arrays** (`folder.json`, `collection.json`) merge as a union: theirs' order, then ours' additions.
  Removals on either side are applied.
- **Strings** (scripts, raw bodies, URLs) are atomic. Different changes on both sides are a conflict. No line merge
  in v1.
- **`body` mode.** When `mode` differs between the sides, the whole `body` is one conflict.
- **`auth` type.** The same: a different `type` on each side makes the whole `auth` one conflict.
- **Unmergeable files.** A deleted side (`null`) is never merged here; Task 3 handles delete/modify. Invalid JSON on
  any side, or kind `other`, gives `unmergeable`.
- **Labels.** `label` is human-readable, for example `URL`, `Header "Authorization"`, `Pre-request script`,
  `Variable "token"`, `Body` or `Auth`.

```ts
// shared/types.ts
export interface SyncChange { path: string; kind: 'added' | 'modified' | 'deleted' | 'renamed'; label: string }  // label e.g. `Request "Login user" in Auth API`
export interface SyncConflictItem {
  id: string                       // the file path
  label: string
  kind: 'fields' | 'file' | 'deleted_remote' | 'deleted_local'
  fields?: { path: string; label: string; ours: string; theirs: string }[]   // values rendered as short text
}
export interface SyncState {
  linked: boolean; branch: string | null; remoteUrl: string | null
  ahead: number; behind: number; changes: SyncChange[]
  merging: boolean; conflicts: SyncConflictItem[]
  identity: { name: string; email: string } | null
}
export type SyncOutcome =
  | { kind: 'up_to_date' } | { kind: 'done'; pulled: number; pushed: number }
  | { kind: 'conflicts'; state: SyncState }
// shared/api.ts — new group `git`
git: {
  state(): Promise<SyncState>
  /** git init if needed, set origin, first fetch; with an existing remote branch, merges it (allowing unrelated histories only here). */
  link(remoteUrl: string): Promise<SyncState>
  /** Clones into an empty directory chosen with the directory picker, then opens it as the workspace (creating workspace.json if the repo has none). */
  clone(remoteUrl: string): Promise<WorkspaceInfo | null>
  setIdentity(name: string, email: string): Promise<void>                      // git config --local
  commit(message: string): Promise<void>                                     // add -A (minus .local/), commit; no-op when nothing changed
  sync(message: string | null): Promise<SyncOutcome>                         // commit (if message) → fetch → merge → push
  pull(): Promise<SyncOutcome>                                               // fetch → merge; refuses with local changes touching incoming files
  push(): Promise<SyncOutcome>
  resolve(id: string, choice: 'ours' | 'theirs' | { fields: Record<string, 'ours' | 'theirs'> }): Promise<SyncState>
  /** Opens the conflicted file in the OS default editor (shell.openPath). */
  openInEditor(id: string): Promise<void>
  /** After all conflicts are resolved: commit the merge, then push if the operation was a sync. */
  finishMerge(): Promise<SyncOutcome>
  abortMerge(): Promise<SyncState>
}
// describe.ts
export function describeChanges(dir: string, changes: GitStatus['changes'], readHead: (path: string) => Promise<string | null>): Promise<SyncChange[]>
export function defaultCommitMessage(changes: SyncChange[]): string   // e.g. "Update 2 requests and 1 environment"
```

**Merge flow.**

1. Run `git merge --no-ff --no-commit origin/<branch>`. If it stops with conflicts, go through each conflicted path:
   1. Read stages `:1:`, `:2:` and `:3:` with `git show`.
   2. Merge them with `mergeJson`.
   3. If the result is `merged`, write the file and `git add` it.
   4. If it is `conflicts`, keep the partial result and its conflicts in memory, keyed by path, and save them to
      `.git/astral-merge.json` so they survive a restart.
   5. If it is `unmergeable`, the item becomes a `file` conflict.
   6. If one stage is missing, the item becomes `deleted_remote` or `deleted_local`.
2. With no conflicts left, commit with git's default merge message, then push when the operation is a sync.
3. With conflicts left, return `conflicts`. `resolve` writes the chosen result and `git add`s or `git rm`s the file.
   `finishMerge` refuses while anything is unresolved.
4. `abortMerge` runs `git merge --abort` and deletes `astral-merge.json`.

**Before operations.** `sync`, `pull`, `push`, `commit` and `link` refuse while a merge is in progress, with
`Finish or abort the merge first`.

**Labels.** `describe.ts` builds labels from the JSON `name` in the working tree, or from HEAD for deleted files:
`Request "<name>" in <collection>`, `Folder "<name>"`, `Collection "<name>"`, `Environment "<name>"`, `Globals`,
`Workspace settings`. Anything else shows the path.

**UI:**

- **Status bar, right side**, before Environments. When the workspace is not linked, it shows a `Set up sync`
  button (lucide `GitBranch`). When it is linked:
  - the branch name;
  - `↑n ↓m` when non-zero;
  - a dot when there are uncommitted changes;
  - a split button: `Sync` (lucide `RefreshCw`, which spins while busy) plus a chevron menu with `Pull only`,
    `Push only`, `Commit…`, `Copy remote URL` and `Unlink…`.

  `Unlink…` asks for confirmation, then removes `origin` only.
- **State refresh.** `git.state()` is refreshed when the window gains focus, after any save, and after every git
  operation. A silent `git fetch` runs every 10 minutes while the workspace is linked, to update `↓m`; its errors are
  ignored.
- **Set up sync dialog.** It has a `Repository URL` field (placeholder `git@github.com:you/repo.git`), a hint that
  the system git and SSH keys are used, and `Link`. Errors are shown inline.
- **Commit dialog**, opened by Sync when there are changes, and by `Commit…`.
  - It lists the changes as `+ / ~ / − / →` rows with their labels.
  - The message textarea is pre-filled with `defaultCommitMessage`.
  - Buttons: `Commit and sync` (or `Commit` when opened from `Commit…`) and `Cancel`.
  - When the identity is missing, `Name` and `Email` fields appear first, with a note that they are saved for this
    repository only.
- **Conflicts dialog.** It opens automatically on a `conflicts` outcome, and from a `Resolve conflicts` banner while
  `merging` is true.
  - **Rows.** One row per item, with its label:
    - `fields` items show a table of Field | Yours | Theirs with radio choices per field, plus `All mine` / `All
      theirs`;
    - `file` items show `Keep mine`, `Keep theirs` and `Open in editor`;
    - deleted items show `Keep mine` / `Delete` or `Keep theirs` / `Delete`.
  - **Footer.** `Abort merge` (it asks for confirmation) and `Finish` (`Finish and push` for a sync), enabled once
    every item is resolved.
- **After a successful operation,** a transient status-bar text shows `Up to date`, `Pulled n, pushed m` or
  `Pushed m` for 4 s. Errors go to the existing error banner.
- **Open from Git.** It sits in WorkspaceGate and the workspace switcher next to `Open folder` and asks for a
  repository URL. The directory picker then chooses where to clone, and the cloned workspace opens.
