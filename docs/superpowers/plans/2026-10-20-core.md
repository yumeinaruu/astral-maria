# Astral Maria Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working desktop app where the user opens a workspace folder, organizes requests in collections and folders, edits environments, sends HTTP requests and inspects responses, with everything stored as plain files on disk.

**Architecture:** Electron app with three parts. The main process owns the disk (workspace, collection and environment stores) and the network (HTTP sender); the preload script exposes one typed `AstralApi` object; the React renderer holds UI state and calls only that API. Stores take a root directory and injected dependencies, so they are tested against temporary directories without Electron.

**Tech Stack:** Electron, TypeScript (strict), React, electron-vite, Vitest (+ Testing Library, jsdom for renderer tests), Zustand, CodeMirror 6, undici, Playwright (Electron end-to-end smoke test). npm. Node 24.

**Spec:** `docs/superpowers/specs/2026-10-20-astral-maria-design.md` (this plan covers delivery step 1 only; import/export, scripts, runner, git sync and load testing get their own plans).

## Global Constraints

- App name: "Astral Maria". Package name: `astral-maria`.
- Node >= 24.11 (`engines` in `package.json`).
- No AI features, no telemetry, no analytics, no update checks, no network traffic except requests the user sends.
- No code, text, icons or branding copied from Postman.
- On-disk layout is exactly: `workspace.json`; `collections/<slug>/collection.json`; `<folder>/folder.json`; `<slug>.request.json` (one file per request); `environments/<slug>.json`; `.local/` (gitignored: current values, secrets).
- Secret variable values never appear in committed files; they live only under `.local/`, encrypted with Electron `safeStorage`.
- All JSON written by the app: 2-space indent, trailing newline, written atomically (temp file then rename), stable key order.
- Renderer runs with `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`; it has no direct network or filesystem access.
- Commit after every task. Every commit message ends with the line `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Git identity is already set in this repository; do not change it.

## Review Focus

- Names that are unsafe as file names (`../../etc/passwd`, `a/b\c`, `CON`, emoji only, 500 characters, duplicates, differing only in case) must produce safe, unique, readable files and never write outside the workspace. (Tasks 2, 4)
- A hand-edited or git-conflicted file (`<<<<<<<` markers, truncated JSON) must be reported as an error for that file only; the rest of the workspace loads and the broken file is never overwritten. (Tasks 3, 4, 5)
- Variables: unknown names stay as `{{name}}` text, a value that references itself or another variable never loops, and literal braces in a JSON body (`{"a":{"b":1}}`) are untouched. (Task 6)
- Requests that fail (DNS failure, connection refused, TLS error, timeout, redirect loop, cancelled) must come back as a normal error result, not an exception reaching the UI; a huge or binary response must be capped and flagged, not freeze the app. (Task 7)
- A request, environment or workspace that disappears from disk while the app is open (deleted in Finder, switched git branch) must not crash the UI; it shows an error and the tree refreshes. (Tasks 8, 9)
